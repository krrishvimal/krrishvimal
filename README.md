## 🧠 How I Build: AI-Native Engineering & Agent Architecture

> **Why AI companies and modern startups trust my development workflow:**  
> Anyone can ask a chat model to write a function. Real AI-native engineering requires treating LLMs as fast, nondeterministic execution engines governed by strict architectural boundaries.

Here is the exact framework I use to ship complex, production-grade applications in days without hallucination or tech debt:

### 1. Spec-Driven Context Architecture (SDCA)
- **Zero Hallucination by Design:** Before writing a single prompt, I define explicit technical specs (`ARCHITECTURE.md`, typed database schemas, and Zod contracts).
- **Context Window Discipline:** I isolate system prompts to narrow scopes (e.g. state management vs. database RPCs) to prevent context pollution and degraded model reasoning.

### 2. Deterministic Type & Schema Anchors
- **TypeScript & Schema-First Invariants:** All data flows through strict TypeScript interfaces and PostgreSQL Row-Level Security (RLS) policies.
- If an AI agent attempts to generate hallucinated API fields or insecure queries, strict type-checking and automated build steps reject the commit immediately.

### 3. Eval & Self-Healing Agent Loops
- **Automated Verification:** I set up continuous feedback loops (`tsc --noEmit`, ESLint rules, transactional database tests) within the agent environment.
- When an error occurs, the agent is fed the precise compiler traceback and test output to independently diagnose, patch, and verify the fix without manual intervention.

### 4. Human Invariance & Security Review
- **100% Code Ownership:** I review every pull request and diff with strict standards for:
  - Database indexing and N+1 query prevention
  - Client/Server boundary security (keeping secrets strictly out of client bundles)
  - Animation compositor layer allocation (`transform-gpu`, `will-change`) for 60–120 FPS fluid mobile interactions
